# Claim-to-test matrix

Every supported claim must name the epistemic tier of each component and its
executable evidence. Lean proves the modeled algorithms. Tests observe shipped
Python behavior corresponding to those models and exercise implementation
refusal paths; they are not a general Python-to-Lean refinement proof.
Deployment claims additionally require the operator controls in
`PRODUCTION_DEPLOYMENT.md`. This matrix is included in
`RELEASE_MANIFEST.sha256`; the release contract then binds the reviewed tree
and test evidence to the signed tag and stamped commit.

## Explicit non-claims

The matrix does not claim that Lean proves arbitrary Python bytecode, a
particular deployed binary, CA identity proofing, host integrity, durable
cross-process replay, complete bypass closure, or every possible training
lifecycle. Those are separate implementation-refinement or deployment claims.
An operator may contract for some of those controls, but that evidence belongs
to the exact deployment rather than this open library.
